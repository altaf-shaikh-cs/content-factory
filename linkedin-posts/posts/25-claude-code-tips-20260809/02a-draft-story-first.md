Three hours into a Claude Code session, things started falling apart.

Responses got shorter. It started forgetting context from earlier in the conversation. I had to keep re-explaining things I'd already explained. By hour four, it was basically useless for the complex refactor I was halfway through.

I did what most people do: started a new session, repasted all the context, and lost another 20 minutes getting back to where I was.

I kept doing this until I learned the real lesson, which had nothing to do with prompts.

Context is the resource. Not tokens in an abstract sense, but the actual working memory Claude has in a session. When it degrades, the session degrades. The fix isn't knowing better tips. The fix is managing context the same way you'd manage memory in a program.

Fresh sessions with a handoff document. Compaction before overflow, not after. Breaking problems into sub-tasks that each fit cleanly in a session window.

Engineers who get this instinctively do well with AI coding tools, because they already think this way. You already know how to decompose a problem. You already know how to isolate a failing test. You already write systems that handle resource limits cleanly. Those instincts transfer directly.

A thread on r/ClaudeAI by someone with 11 months of daily use and 569 upvotes covers 25 tips. Most of them are variations on this one pattern. That's not a coincidence.

The tools reward the same thinking that good engineering rewards. Manage the context, break the problem down, and let the reps build the intuition.

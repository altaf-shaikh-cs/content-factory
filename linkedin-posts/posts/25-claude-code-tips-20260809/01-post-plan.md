# Post Plan — 25-claude-code-tips

## Core Insight
Engineers who get the most from AI coding tools aren't the ones who memorize the most tips — they're the ones who use the tools long enough and deeply enough to rebuild their intuitions from scratch.

## Target Audience
Early-to-mid career software engineers actively using Claude Code or similar AI coding assistants — people who read articles like "25 tips" and wonder why those tricks don't stick in practice.

## Structure
1. The trap: tips lists feel productive but skill comes from volume of use, not from knowing tricks
2. The one pattern that actually moves the needle: context management (fresh sessions, handoff documents, early compaction before overflow)
3. Why engineers specifically have an advantage: you already know how to break down problems, write tests, isolate variables — those skills transfer directly
4. The billion-token rule: intuition builds through reps, not reading. The only way to get good is to use the tool so much that you rediscover the lessons yourself

## CTA
If you're using Claude Code, what's the one habit that's changed how you work? Share below.

## Tone Range

## Angle Assignments

**Angle A: Story-first**
Open with a personal moment where a Claude Code session broke down — context overflow at hour three, output degrading — and the fix that changed everything (handoff docs, fresh sessions, early compaction). Let the insight about context management emerge from the story.

**Angle B: Bold claim-first**
Lead with the bottleneck claim: the limiting factor in Claude Code workflows isn't prompts, isn't the model, isn't knowing more tricks — it's context management. Engineers have the right instincts already; the engineering skills transfer directly.

**Angle C: Contrarian**
Challenge the genre of the source material itself. "Reading 25 tips about Claude Code will not make you better at Claude Code." Open with that line, then explain why: skill is reps, not knowledge. The billion-token rule — intuition compounds through use, not through reading. The tips you keep are the ones you discovered yourself.

**Chose Contrarian because:** decision rule 5 (none of the above structural matches — no clear personal confession, no checklist method, not structurally comparative, no single shocking stat). The source is literally a tips list, and flipping that frame creates friction the other two angles structurally cannot — plus contrarian is the highest-performing underused angle per tracker data.

## Core Insight

Coding is not becoming irrelevant, it is becoming the floor instead of the ceiling. Per Andrew Ng's analysis of 10,000 job postings, the four skills that actually separate engineers in 2026 are: building and deploying AI applications (and controlling their unpredictability), software engineering fundamentals (to catch the tradeoffs AI silently makes for you), using coding agents well (knowing their limits and trusting them correctly), and shaping what gets built at all. You are not a bricklayer anymore, laying bricks faster than the next person. The robot lays bricks now. You are the architect deciding where the wall goes and why.

## Target Audience

Early-to-mid career software engineers and senior ICs in India's tech hubs (Mumbai, Bengaluru, Delhi, Hyderabad — this account's core geography) who use AI coding agents daily, have felt the "is my job disappearing" anxiety, and want a concrete answer instead of a vibe. Not AI-curious beginners, not executives.

## Structure

1. The reframe: you used to be the bricklayer who built perfect walls. Now a robot lays bricks faster than you. Your value was never the bricklaying.
2. Set-up: Andrew Ng looked at 10,000 job postings to find which software skills actually matter in 2026. Four came back. Coding isn't one of them, but none of them work without it.
3. Skill 1: Build and deploy AI applications. Not "can you call an API." Normal software is predictable; AI is not, ask it the same question twice and get two different answers. The real skill is controlling that unpredictability through disciplined evals and error analysis.
4. Skill 2: Software fundamentals matter more, not less. Every software decision is a tradeoff (fast, secure, cheap, pick your compromises). Tell an AI to hit all three and it will quietly pick which one loses. You won't know until it breaks in production, unless you understand the tradeoff yourself.
5. Skill 3: Use coding agents well. Know what they're good at, where they fail, how much to trust them. One careless instruction can wipe a production database. And do all of this efficiently, time and tokens both count.
6. Skill 4: Shape the build. You're not just executing tickets anymore. Deciding which problem is worth solving is now part of the job.
7. The diagnostic (saveable slide, placed early): a quick self-check across the four skills, one line each on what "doing it" vs "skipping it" looks like.
8. Close: if you're learning AI, don't just learn to write code. Learn to think like a senior engineer. Plus the CTA.

## CTA

An open, self-check question, not a poll: "Of the four, which one are you actually building, and which one are you just hoping the agent handles for you?"

## Tone Range

Educational, authoritative on the framework (it's Andrew Ng's, attributed, not the author's own claim), grounded with the bricklayer/architect image so it doesn't read like a listicle.
